정면 원본 한 장에서 같은 캐릭터의 다른 방향을 만든다. 기본 산출물은 원본 정면 1개와 새로 생성한 7개 방향이다. 새로운 캐릭터를 디자인하거나 다른 화풍으로 바꾸지 않는다. 사용자가 계획·프롬프트만 요청하면 이미지 생성 없이 해당 내용만 제공한다.

## 입력과 내장 예제

- 사용자가 지정한 정면 이미지를 최우선 정체성 기준으로 삼는다. 이미지가 여러 개면 원본, 스타일 참고, 수정 대상의 역할을 구분한다.
- 자원 경로는 이 참조 문서의 폴더가 아닌 통합 스킬 루트(`SKILL.md`가 있는 디렉터리)를 기준으로 해석한다. 과거 대화의 파일 경로나 외부 서비스 식별자에 의존하지 않는다.
- `assets/styles/example-golem-front.png`는 사용자가 만든 이끼 바위 골렘의 예제 정면이다. 사용자가 내장 예제, 이 골렘, 샘플로 시연하라고 할 때 사용할 수 있다. 다른 캐릭터 요청의 얼굴·비율·질감을 이 골렘으로 덮어쓰지 않는다.
- 이 모드에 사용할 정면이 없고 새 캐릭터 생성이나 내장 예제 사용도 요청하지 않았다면 정면 이미지를 한 번 요청한다. 설명에서 새 캐릭터의 8방향을 만드는 요청은 루트 지침의 생성→회전 순서를 따른다. 필요한 원본을 추측하거나 임의의 캐릭터로 대체하지 않는다.

## 실제 한계

- 단일 정면에서 보이지 않는 후두부, 등, 장식의 뒷면, 무기의 두께는 실제 정보를 복원할 수 없다. 관찰한 특징과 새로 정한 후면 가정을 분리한다.
- 기본은 보이는 형태를 자연스럽게 이어 최소한의 후면을 만든다. 임의의 새 문양, 등 장식, 무기나 돌출물을 추가하지 않는다. 사용자에게 짧게 후면이 추정임을 알리고 불필요한 승인 절차 없이 진행한다.
- 보이지 않는 면까지 정확히 재현해야 한다면 후면·측면 기준도 요청하거나 제공된 실제 3D 모델·회전 자료를 활용한다. 이미지 생성만으로 완벽한 기하학적 회전이나 픽셀 단위 일치를 보장하지 않는다.

## 범용 적용

- 입력 원본의 종족·화풍·구조를 따른다. 두 눈, 두 팔, 사람형 머리 비율, 파스텔 질감, 특정 무기나 골렘의 돌·이끼를 공통 규칙으로 강제하지 않는다.
- 사람형·네발형·다족형·무족형·부유형 등 실제 구조와, 크롭·가림 여부를 먼저 기록한다. 원본에 없는 팔다리·얼굴·복장을 복원된 사실처럼 추가하지 않는다.
- 지상형은 확인 가능한 발 접점과 몸 기준점을, 부유·수중·날개형은 몸 중심 등 확인한 기준점을 사용한다. 발이 없거나 보이지 않으면 접지선을 강요하지 않는다. 꼬리·무기·날개를 포함한 알파 상자의 중심과 최하단은 이 기준점과 구분한다.
- 불투명 배경이나 알파 없는 입력에서는 수치 검사의 제한을 기록하고 시각적 대응 부위 검사를 사용한다. 스크립트가 배경을 자동 분리하거나 종족을 판별한다고 가정하지 않는다.
- 여러 개체가 있는 입력에서는 사용자가 지정한 대상을 선택한다. 대상이 불명확하면 하나를 임의로 대체하지 말고 확인한다. 온전한 정면이 아닌 입력은 추가로 추정할 면과 잘린 부위를 구분한다.
- 회전 대칭이 강한 대상은 일부 방향이 거의 같을 수 있다. 방향을 억지로 구별하려고 새로운 눈·무늬·돌출물을 추가하지 않는다. 애니메이션 입력은 사용할 기준 프레임을 명확히 하고, 파일 하나의 첫 프레임 검사로 전체 애니메이션을 검수했다고 말하지 않는다.

## 방향 규약

[방향 정의](directions.json)를 읽는다. 기준 카메라를 고정하고 캐릭터 전체를 수직축으로 회전한다. 양의 각도는 정면에서 화면 왼쪽을 향하도록 도는 순서다. 얼굴만 돌리거나 카메라 높이·시점을 바꾸지 않는다.

| 순서 | 파일 | 각도 | 보이는 방향 |
| --- | --- | --- | --- |
| 0 | `00_front.png` | 0° | S, 정면, 관객을 향함 |
| 1 | `01_front_left.png` | 45° | SW, 화면 왼쪽을 향한 앞 사선 |
| 2 | `02_left.png` | 90° | W, 화면 왼쪽을 향한 옆면 |
| 3 | `03_back_left.png` | 135° | NW, 화면 왼쪽을 향한 뒤 사선 |
| 4 | `04_back.png` | 180° | N, 정후면, 관객에게 등을 보임 |
| 5 | `05_back_right.png` | 225° | NE, 화면 오른쪽을 향한 뒤 사선 |
| 6 | `06_right.png` | 270° | E, 화면 오른쪽을 향한 옆면 |
| 7 | `07_front_right.png` | 315° | SE, 화면 오른쪽을 향한 앞 사선 |

사용자가 다른 파일명·방향 순서를 지정하면 그 규약을 사용하고 매핑을 명시한다. 나침반 표기는 스프라이트의 방향 키이며, 그림 자체를 위에서 내려다보라는 뜻이 아니다.

## 제작 순서

### 1. 원본과 특징 고정

먼저 [공통 잔여물 검사](artifact-review.md)로 최초 입력과 후속 기준을 구분한다. 명확한 오류가 있으면 최초 파일은 보존하고 국소 보정 파생본을 검수해 채택한다. 아래 원본 고정은 채택한 제작 기준에 적용하며, 보정본을 최초 입력과 바이트 동일한 파일이라고 설명하지 않는다. 오류가 있는 기준을 다음 방향에 전파하지 않는다.

1. 원본을 이미지 보기 도구로 실제로 열고 캔버스 크기, 배경, 카메라 높이, 머리·몸 비율, 자세, 발 접지선, 색과 질감을 확인한다.
2. [특징 기록 양식](design-lock-template.json)을 바탕으로 작업용 `design-lock.json`을 작성한다. 눈·장식·의상·무기·마디 수·큰 무늬에 고유 ID를 주고, 몸의 어느 면과 해부학적 좌우에 붙는지, 모양·개수·인접 관계와 방향별 가림을 기록한다. 원본의 2D 좌표와 추정 3D 위치를 구분하고 관찰 불가능한 값은 `unknown`으로 남긴다. 미세 입자 전체를 추적 가능한 특징으로 취급하지 않는다.
3. 화면 기준 좌우와 캐릭터 해부학적 좌우를 구분한다. 예를 들어 정면의 화면 오른쪽 손은 일반적인 사람형의 해부학적 왼손이다. 무기가 화면의 같은 쪽에 계속 남도록 지시하지 않는다.
4. 원본 정면은 다시 그리지 않는다. 원본 파일은 확장자와 바이트를 유지해 보존하고 출처 경로를 기록한다. 원본이 PNG이면 `00_front.png`에 그대로 복사할 수 있다. 다른 형식의 원본을 PNG로 내보내거나 정규화했다면 별도 파생본으로 구분하고, PNG 정면이 원본 파일과 바이트까지 동일하다고 주장하지 않는다.
5. [품질 검사와 보정](quality-and-repair.md)을 읽고 원본의 캔버스, 알파 경계, 상대 높이, 위·아래 여백을 수치로 기록한다. 값은 매 원본에서 계산하며 골렘 예제의 비율을 다른 캐릭터에 고정하지 않는다. 알파 경계의 최하단은 실제 발 접점·엔진 피벗과 다른 진단 지표다.

### 2. 측면·후면 기준 만들기

1. [생성 템플릿](turnaround-template.md)에 원본의 고정 특징, 목표 방향, 보이는 면과 가려지는 면을 넣는다.
2. W(왼쪽 옆면), E(오른쪽 옆면)를 각각 원본을 직접 참조해 생성한다. 원본을 기본 이미지 입력으로 매번 전달한다.
3. N(정후면)은 원본과 확인한 좌우 측면을 함께 참조한다. 최소 후면 가정을 일관되게 적용한다.
4. 각 이미지를 만들자마자 실제로 열어 방향·특징을 비교하고 수치 검사를 실행한다. 잘못된 방향, 손바뀜, 큰 확대·축소, 핵심 특징의 누락은 보정한 다음 다음 방향의 기준으로 사용한다. 방향만 맞았다고 기준 이미지 검수를 끝내지 않는다.
5. 정면과 W/E/N을 같은 캔버스 배율로 모아 1차 검수한다. `angle_check`, `identity_check`, `framing_check`, `unresolved_items`를 각각 기록하고 기준 사용 여부를 명시한다. 수치 경고는 시각적으로 판단해 `resolved`, `explained_by_projection`, `needs_review` 중 하나로 처리한다. 미해결 중요 오류가 있는 이미지는 `accepted_anchor`로 쓰지 않는다. 남은 사소한 차이를 허용하고 진행할 때는 `provisional_anchor`와 남은 차이를 기록한다.
6. 기본은 내부 검수 후 진행한다. 사용자가 중간 확인을 요청했거나 결과를 바꾸는 필수 정보가 없을 때만 확인을 요청하고, 방향마다 승인을 요구하지 않는다.

### 3. 대각선 만들기

- SW: 정면 원본 + 확인한 W를 참조한다.
- NW: 정면 원본 + 확인한 N과 W를 참조한다.
- NE: 정면 원본 + 확인한 N과 E를 참조한다.
- SE: 정면 원본 + 확인한 E를 참조한다.
- 직전 생성 결과 하나만 계속 이어받지 않는다. 모든 방향에서 변경되지 않은 원본 정면과 동일한 특징 기록을 함께 사용한다.
- 한 장에 8방향을 새로 그리는 방식은 미리보기 요청일 때만 사용한다. 기본은 방향별 개별 생성과 검수다. 여러 방향이 담긴 미리보기를 정확한 개별 파일이 완성된 것으로 보고하지 않는다.

### 4. 수치 검사와 최소 보정

- `scripts/measure_sprite_framing.py`로 원본과 생성물의 실제 크기·알파 경계·상대 높이·위아래 위치를 측정한다. Pillow가 필요하며 의존성은 `scripts/requirements.txt`에 있다. 실행 환경에 없으면 이용 가능한 이미지 검사 도구로 확인하고, 자동 수치 검사가 실행됐다고 말하지 않는다.
- 기본 검토 기준은 보이는 높이의 정면 대비 차이 3%, 위·아래 경계의 이동 1.5% 캔버스 높이다. 이는 작업용 경고 기준이며 검증된 보편 품질 기준이나 자동 불합격 판정이 아니다. 무기·모자·꼬리와 원근에 따른 자연스러운 변화는 별도로 판단한다. 폭이나 알파 상자의 중심을 강제로 같게 만들지 않는다.
- 크기·배치만 틀렸다면 대상 이미지를 첫 참조, 원본을 둘째 참조로 넣고 재프레이밍만 요청한다. 원본에서 확인한 몸의 위쪽 기준, 몸 중심 또는 실제 접점과 여백을 숫자로 제시한다. 다른 각도를 처음부터 다시 만들며 이미 맞은 특징까지 바꾸지 않는다.
- 중요한 무늬가 틀렸다면 특징 ID와 실제 몸의 면, 개수·모양, 목표 방향에서의 가림을 지목해 해당 특징만 수정한다. 가려져야 할 무늬를 억지로 보이게 하지 않는다.
- 보정 후 다시 측정하고 실제 이미지를 확인한다. 개선 전후 수치, 생성 호출과 남은 차이를 기록한다. 경고를 없애려고 임의로 임계값을 느슨하게 바꾸거나 미해결 항목을 통과 처리하지 않는다.

## 회전 중 유지할 조건

- **동일한 캐릭터와 자세:** 관절 자세, 표정의 성격, 장비와 의상은 유지한다. 원근에 따른 겹침과 길이 변화는 허용하되 새 동작이나 새 장비로 바꾸지 않는다.
- **동일한 카메라:** 고정된 높이·기울기·투영 감각·배율·배경을 유지한다. 방향마다 머리나 발을 같은 크기로 다시 맞추거나 무기까지 꽉 채우려고 확대하지 않는다.
- **동일한 몸 기준 위치:** 몸 중심과 발 접지선·회전 중심을 가능한 한 맞춘다. 무기나 꼬리 때문에 바깥 실루엣의 폭이 달라지는 것은 정상이다.
- **몸에 고정된 비대칭:** 문양, 이끼, 가방, 흉터는 같은 몸 표면에 남아 회전하며 가려져야 한다. 화면 좌우 위치를 고정하지 않는다.
- **같은 손과 소품:** 무기를 든 해부학적 손과 무기 구조를 유지한다. 옆면·후면에서 가려져도 반대 손으로 옮기지 않는다. 망토는 같은 어깨 부착점에서 이어진다.
- **자연스러운 가림:** 측면의 먼 눈·팔·다리는 가려질 수 있다. 정후면에 눈·입·앞면 보석을 억지로 그리지 않는다. 큰 모자·뿔·등껍질·무기는 각도에 따라 보이는 면이 달라져야 한다.
- **같은 화풍:** 원본의 윤곽, 색, 세부 밀도, 질감 강도와 부드러운 조명을 유지한다. 화면 기준 광원은 고정하되 면의 방향에 따른 음영은 자연스럽게 변화시킨다.
- **눈의 반짝임:** 원본 눈의 하이라이트 유무·색·크기와 반사·발광 방식을 기록한다. 원본에 작은 하이라이트가 있으면 보이는 눈에서 같은 표현을 유지하고 시점·광원에 맞게 자연스럽게 조정한다. 반사광은 몸에 붙은 문양과 구분한다. 원본이 무광이면 별도 요청 없이 추가하지 않으며, 가려진 눈·감은 눈·후면에는 반사광을 억지로 그리지 않는다.
- **좌우 반전 금지:** 기본은 좌우를 별도로 생성한다. 비대칭 장식·소품·표식·조명까지 확인하고 사용자가 반전을 허용한 경우에만 반전 파생본을 사용한다. 반전본을 독립적으로 생성한 새 시점이라고 설명하지 않는다.

## 이미지 도구 사용

- 노출된 이미지 생성·편집 도구를 사용한다. 참조 파일명만 프롬프트에 적지 말고 실제 이미지 입력으로 전달한다.
- `image_gen.imagegen` 계열이 `referenced_image_paths`를 지원하면 원본 정면과 해당 방향의 기준 이미지의 실제 절대 경로를 전달한다. 모든 입력이 로컬 파일이면 최근 이미지 개수 옵션과 함께 사용하지 않는다.
- 배경 투명도는 기본적으로 원본을 따른다. 투명 배경 요청이면 도구의 실제 투명 옵션도 설정한다.
- 파일명·각도·크기 인자는 도구가 실제 지원할 때만 사용한다. 캔버스 규격을 강제할 수 없으면 생성 후 실제 치수를 확인하고 정규화가 필요한 상태를 숨기지 않는다.
- 이미지 생성 도구가 없으면 수행 가능한 범위를 설명한다. 실제 생성·검수·완료를 꾸며내지 않는다.

## 결과 검수와 전달

1. 파일명만 믿지 말고 실제 모습을 보고 요청 방향과 특징의 가림이 맞는지 확인한다. 회전 대칭인 대상에는 불필요한 방향 차이를 강제하지 않는다. 특히 NW/NE가 앞 사선으로 잘못 나온 경우, E/W가 단순 반전인 경우를 확인한다.
2. 원본과 각 기준 방향을 나란히 보고 비율·큰 무늬·머리 장식·손·장비·질감의 변화를 확인한다. 가림에 따른 자연스러운 차이와 실제 디자인 변경을 구분한다.
3. 중요한 오류는 해당 방향만 수정하고, 그 방향을 참고한 대각선도 필요한 경우 다시 확인한다. 해결되지 않은 항목은 `needs_review`로 남긴다.
4. 원본과 7개 생성 이미지를 구분해 순서대로 제공한다. 8방향이 실제로 완성됐을 때만 완료라고 말한다. 작업 중에는 묶음 단위로 진행 상황을 알린다.
5. 파일 출력을 지원하면 실제 이미지를 `00_front.png`부터 `07_front_right.png`로 묶고, `manifest.json`에 방향·실제 치수·참조 경로·검수 상태·후면 가정과 호출 횟수를 남긴다. 수치 검사 결과는 `framing-report.json`으로 별도 보존한다. 원본과 다른 치수·배율·실제 발 접점·피벗 문제가 해결되지 않았다면 게임용 정렬 완료로 표현하지 않는다. 캔버스 규격이 같거나 수치 경고가 없다는 이유로 방향·동일성·피벗 검수가 통과했다고 말하지 않는다.
6. 미리보기는 완성된 실제 파일을 사용해 만든다. 새로 그린 비교 시트를 원본 파일의 정확한 복사 미리보기라고 주장하지 않는다.
7. 회전 미리보기는 원본과 모든 방향의 전체 캔버스를 같은 비율로 표시해 흔들림을 드러낸다. 프레임별 알파 상자 맞춤으로 차이를 숨기지 않는다. 별도 요청으로 정렬 파생본을 만들었다면 원본 파일과 변환 내역을 구분한다.
