# 파스텔 캐릭터 생성·부분 수정 절차

캐릭터·몬스터 설명을 실제 이미지로 제작한다. 사용자가 프롬프트만 요청하지 않았다면 프롬프트 설명으로 끝내지 말고 이미지 생성 도구를 사용한다.

## 내장 기준 이미지

자원 경로는 이 참조 문서의 폴더가 아닌 통합 스킬 루트(`SKILL.md`가 있는 디렉터리)를 기준으로 해석한다. 설치 경로가 바뀌어도 동작하도록 절대 경로, 과거 대화, Library 식별자, 외부 URL에 의존하지 않는다.

| 파일 | 역할 |
| --- | --- |
| `assets/styles/style-king.png` | 눈에 작은 하이라이트가 있는 최종 왕. 둥근 형태, 짧은 비율, 색감, 음영과 질감의 주 기준 |
| `assets/styles/style-original-king.png` | 128×128 원본. 단순한 덩어리와 절제된 디테일을 확인하는 보조 기준 |

내장 이미지는 스타일 기준이다. 새 캐릭터에 왕관, 흰 수염, 보라색 로브 등을 자동으로 복제하지 않는다. 원본의 작은 해상도를 픽셀 격자를 그리라는 지시로 해석하지 않는다.
128×128 원본은 형태와 단순화 수준의 보조 자료다. 눈의 현재 기본 표현은 하이라이트가 추가된 최종 왕과 3인조를 따른다.

## 제작 순서

1. 사용자의 설명에서 종족·외형·색상·복장·무기·성격·수량을 추출한다. 시점·포즈·행동·표정·배경·화면 비율이 있으면 함께 반영한다. 누락된 선택 사항은 자연스럽게 정하고 형식 작성이나 재첨부를 요구하지 않는다.
2. 스킬의 실제 설치 루트를 확인하고 위 이미지들의 경로를 해석한다. 생성 전 `style-king.png`를 이미지 보기 도구로 확인한다. 필요하면 원본도 확인한다. 파일명만 읽고 이미지 열람을 대신하지 않는다.
3. [생성 템플릿](generation-template.md)을 읽고 사용자의 설명을 결합한다. 외형과 연출은 사용자 요청을, 공통 그림체는 내장 이미지를 따른다.
4. 이미지 생성 도구에 내장 PNG를 **실제 참조 이미지 입력으로 전달**한다. 프롬프트에 파일명만 쓰고 이미지를 빼먹지 않는다. 기준 왕과 3인조를 기본 참조로 사용하고, 원본은 추가 비교가 필요할 때 사용한다.
5. [공통 잔여물 검사](artifact-review.md)를 수행한 뒤 생성 결과를 보고 공통 스타일, 신체 연결, 의상 겹침, 요청한 무기와 구도를 확인한다. 중요한 누락이나 명백한 오류가 있으면 해당 부분을 수정한다. 생성하지 않은 이미지나 확인하지 않은 품질을 완료했다고 말하지 않는다.
6. 이미지를 제공하고 변경점을 짧게 설명한다. 새로 만든 이미지를 고정 기준 파일에 덮어쓰지 않는다.

### 이미지 도구 연결

- `image_gen.imagegen` 또는 `image_gen__imagegen`을 사용할 수 있으면 번들 PNG의 실제 로컬 절대 경로를 `referenced_image_paths`로 전달한다. 실행 중인 환경의 도구 스키마와 지침을 따른다.
- 로컬 경로로 참조를 모두 전달할 수 있으면 `num_last_images_to_include`를 함께 사용하지 않는다. 새 대화에서도 내장 이미지로 제작할 수 있어야 한다.
- 기본 배경은 투명이므로 도구에 투명 배경 옵션이 있으면 활성화한다. 사용자가 배경이나 장면을 지정하면 그 요청을 따른다.
- 다른 이미지 생성 도구에서는 동일한 파일을 해당 도구의 이미지 참조 입력에 전달한다. 지원되지 않는 도구 이름이나 매개변수를 만들어내지 않는다.
- 이미지가 직접 표시되면 중복 표시를 피한다. 이미지 생성 도구가 없거나 참조 입력을 사용할 수 없으면 한계를 명확히 말하고, 실제 이미지가 만들어졌다고 주장하지 않는다.

## 기본값과 자유도

- 특징 설명 한두 문장만으로 진행한다. 기본은 캐릭터 하나의 전신과 투명 배경이다. 명시되지 않은 시점·포즈는 특징을 잘 보여주도록 정한다.
- **정면, 대칭 자세, 고정된 손 위치를 강제하지 않는다.** 측면·후면·사선, 공격·점프·달리기·앉기, 확대 구도 등 사용자가 지정한 연출을 따른다.
- 사람형의 머리와 머리 장식은 서 있는 기본 비율에서 전체 높이의 약 60~65%로 잡는다. 동작·원근에 맞게 변화시키고, 슬라임·동물·다족 몬스터에 사람형 비율이나 두 팔을 강요하지 않는다.
- 여러 캐릭터를 요청하면 동일한 렌더링과 크기 기준을 적용하고, 별도 지시가 없으면 서로 닿지 않게 배치한다. 개별 파일 요청은 각각 출력한다.
- 무기 크기는 사용자 설명을 우선한다. 별 지팡이는 별의 중심이 모자 위가 아닌 얼굴 옆 높이에 오도록 잡고, 손잡이는 쥔 손 아래에서 발 근처까지 이어지게 한다. 큼직한 둥근 오각별을 사용하고 다른 무기에 별 모양을 자동으로 붙이지 않는다.
- 사용자의 새 디자인·구도·배경 지시가 기본값보다 우선한다. 변경을 요청하지 않은 부분은 기존 디자인을 유지한다.

## 부분 수정

- 수정할 기존 이미지와 내장 스타일 기준을 구분한다. 기존 이미지는 캐릭터 정체성과 구도의 기준이며, 내장 이미지는 공통 화풍의 기준이다.
- 요청한 부위만 고친다. 얼굴·머리 크기·복장·색·포즈까지 불필요하게 재설계하지 않는다.
- 좌우는 캐릭터 기준인지 화면 기준인지 문맥으로 파악한다. 모호하면 '활을 든 팔', '빈손 쪽'처럼 실제 부위로 특정한다.
- 한 소매 색상을 고칠 때 망토까지 같은 색으로 바꾸지 않는다. 망토는 어깨 뒤에서 이어지고 소매와 분리되어야 한다.

## 눈의 하이라이트

- 새로운 캐릭터의 일반적인 눈에는 보이는 눈마다 작은 아이보리·흰색 원형 또는 짧은 타원 하이라이트 1개를 넣는다. 기존의 작고 짙은 남색 타원 눈을 유지하면서 생기를 더한다.
- 기본 크기는 눈 높이의 약 15~20%를 참고하되 실제 해상도와 눈 형태에 맞춘다. 기본 광원이 좌상단이면 하이라이트도 눈 안쪽 좌상단에 작게 두고, 다른 조명 요청이 있으면 그에 맞춘다.
- 눈동자·홍채를 새로 크게 만들거나 별 모양 반짝임, 과도한 다중 하이라이트, 광륜을 추가하지 않는다. 눈의 작은 반사광과 옷·몸의 무광 파스텔 질감을 함께 유지한다.
- 외눈·다안·감은 눈·가려진 눈·눈 없는 생물·발광 눈 등 종족과 디자인 지시를 우선한다. 없는 눈이나 가려진 눈에 반사광을 만들지 않는다. 발광과 표면 반사광을 구분한다.
- 기존 이미지의 부분 수정에서는 원본 눈 표현을 보존한다. 하이라이트 추가·변경을 요청했을 때만 눈을 수정한다. 새 캐릭터 생성의 기본값을 이유로 다른 부분 수정 중 눈까지 바꾸지 않는다.

## 결과 점검

- 손·무기 파지부·관절·실루엣 경계에 의도하지 않은 점·짧은 선·돌출 조각이 없는가? 정상 눈 반짝임·활시위·알파 가장자리를 보존했는가?

- 기준 이미지와 나란히 놓아도 둥근 형태, 작은 몸, 단순한 눈, 부드러운 음영, 고운 입자와 색감이 같은 세트로 보이는가?
- 새로 만든 일반적인 눈에는 적절한 작은 하이라이트가 있는가? 눈의 수·모양·색을 바꾸거나 감은 눈·가려진 눈에 반짝임을 추가하지 않았는가?
- 굵은 외곽선, 거친 크레파스 빗금, 자수·직물 같은 재질, 과한 금색 장식이나 애니메이션식 큰 눈으로 변하지 않았는가?
- 종족에 맞는 팔다리 개수와 연결을 지키는가? 해당 시점에서 자연스럽게 가려지는 부위를 억지로 드러내지 않았는가?
- 좌우 소매는 디자인에 맞는가? 망토가 겨드랑이에 끼거나 팔·손과 합쳐지지 않았는가?
- 무기를 자연스럽게 쥐고 있으며 손잡이와 끝 장식이 연결되는가? 요청한 크기를 반영했는가?
- 전신 구도에서는 장식과 무기 끝까지 보이는가? 확대·부분 구도에서는 의도한 잘림을 따르는가?

## 짧은 입력 예

- `초록색 피부와 큰 귀를 가진 고블린. 가죽 조끼를 입고 나무 몽둥이를 들고 있어.`
- `하늘색 슬라임. 머리 위에 작은 새싹이 있고 겁이 많은 표정.`
- `하얀 늑대 몬스터. 목에 붉은 스카프를 두르고 옆모습으로 달리는 장면.`
- `노란 머리 여자 마법사. 보라색 모자와 로브, 큼직한 별 지팡이. 뒤돌아보며 점프.`
